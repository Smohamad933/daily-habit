# پلنر روزانه من

وب‌اپ فارسی و راست‌به‌چپ برای برنامه‌ریزی روزانه، تسک‌ها، عادت‌ها، اهداف و گزارش پیشرفت. رابط جدید مینیمال و موبایل‌فرست است؛ تمرکز آن روی لیست کارها، رنگ سبز آرام، آیکون‌های خطی SVG و نوار پایین موبایل است.

## امکانات کاربر

- برنامه‌ریزی ساعتی و تقویم جلالی واقعی؛ ماه‌های ۲۹، ۳۰ و ۳۱ روزه و اسفند کبیسه
- تسک‌های روزانه، هفتگی و موردی با ساعت، اولویت، انجام/بازگشت و گزارش علت انجام‌نشدن
- عادت‌های روزانه با ثبت پیشرفت ۰ تا ۱۰۰، زنجیره و نمودار هفت‌روزه
- اهداف هفتگی، ماهانه، سه‌ماهه، شش‌ماهه و سالانه با مصاحبه و برنامه گام‌به‌گام
- یادداشت‌ها، تست شخصیت، ایجنت‌های قانون‌محور و گزارش روزانه/هفتگی/ماهانه
- اعلان داخل برنامه، Notification API مرورگر و زیرساخت Web Push/VAPID
- دارک‌مود، لایت‌مود، طراحی ریسپانسیو و ناوبری پایین موبایل
- پنل مدیریت برای کاربران، محتوا و خروجی اکسل

## پنل مانیتورینگ افراد

پنل مانیتورینگ مستقل در مسیر زیر قرار دارد:

```text
/monitoring/login.php
```

پنل شامل نمای کلی، افراد و شاخص پیشرفت، رویدادهای سامانه، صفحه جزئیات کاربر، وضعیت اتصال و راهنمای امنیت است. رویدادهای ثبت‌شده شامل ورود، بازدید صفحات و اقدام‌های اصلی API هستند.

### نصب اتصال MySQL

1. افزونه‌های `pdo_mysql` و `pdo_sqlite` را در `php.ini` فعال کنید.
2. مطمئن شوید پوشه `data` برای کاربر IIS (معمولاً `IIS_IUSRS` یا `IUSR`) دسترسی `Modify` دارد.
3. این آدرس را باز کنید:

```text
/monitoring/install.php
```

4. مشخصات MySQL را وارد کنید. نصب‌کننده در صورت داشتن دسترسی، دیتابیس را می‌سازد، جدول‌های مانیتورینگ را ایجاد می‌کند و اتصال را در فایل مسدودشده‌ی `data/monitoring_mysql.php` می‌نویسد.
5. مدیر اولیه‌ی پنل:

```text
Username: Mohusyn
Password: Smosh1387
```

6. بعد از نصب، `monitoring/install.php` را محدود یا حذف کنید و رمز اولیه را تغییر دهید.

### معماری داده و حریم خصوصی

برای اینکه نصب عادی برنامه بدون نصب دیتابیس جدا هم کار کند، داده‌ی اصلی برنامه در SQLite باقی می‌ماند. مانیتورینگ یک mirror مستقل در MySQL دارد و شاخص‌ها، وضعیت‌ها و رویدادهای غیرحساس را در آن نگه می‌دارد. رمز مدیر با `password_hash` ذخیره می‌شود؛ رمز کاربران، متن یادداشت‌ها و فرم‌های خصوصی به MySQL مانیتورینگ منتقل نمی‌شوند. IP خام ذخیره نمی‌شود و فقط هش یک‌طرفه برای تفکیک نشست‌ها ثبت می‌شود.

## فونت ابَر (Abar)

در CSS، فونت `Abar` اولویت دارد و سپس به `Vazirmatn` و `Tahoma` برمی‌گردد. چون فایل فونت تجاری همراه مخزن قرار نگرفته است، نسخه‌ی قانونی وب‌فونت را با نام‌های زیر در `assets/fonts/` قرار دهید:

```text
assets/fonts/Abar-Regular.woff2
assets/fonts/Abar-SemiBold.woff2
```

اگر فایل‌ها وجود نداشته باشند، رابط همچنان با فونت جایگزین اجرا می‌شود.

## نصب روی IIS

### پیش‌نیازها

- IIS و URL Rewrite
- PHP 8.1 یا بالاتر، نسخه Non Thread Safe مناسب IIS
- افزونه‌های اصلی:

```ini
extension=pdo_sqlite
extension=sqlite3
extension=mbstring
extension=fileinfo
```

- برای پوش و مانیتورینگ اختیاری:

```ini
extension=openssl
extension=curl
extension=pdo_mysql
extension=zip
```

### تنظیم FastCGI

در IIS روی `Handler Mappings` یک Module Mapping برای `*.php` با `FastCgiModule` بسازید و مسیر زیر را متناسب با نصب خود تنظیم کنید:

```text
C:\php\php-cgi.exe
```

پوشه پروژه را مثلاً در `G:\web-site\test` قرار دهید. فایل `web.config` اصلی، PHP، URL Rewrite، MIME فونت‌ها و مسدودسازی `data`، `includes` و `config` را تنظیم می‌کند.

سپس:

```text
http://localhost/test/install.php
```

را باز کنید تا SQLite و مدیر پیش‌فرض ساخته شود. برای داده‌ی نمونه می‌توانید `?demo=1` را باز کنید. بعد از نصب، فایل نصب اصلی را حذف یا محدود کنید.

## ساختار مهم

```text
├─ dashboard.php, planner.php, tasks.php, habits.php
├─ calendar.php, notes.php, goals.php, agents.php
├─ personality.php, reports.php, notifications.php, profile.php
├─ admin/                 پنل مدیریت اصلی
├─ monitoring/            پنل مانیتورینگ مستقل و نصب MySQL
├─ includes/              احراز هویت، SQLite، جلالی، AI و mirror مانیتورینگ
├─ assets/css/style.css   رابط کاربری سبز و مینیمال
├─ assets/fonts/          محل فونت قانونی Abar
├─ data/                  SQLite و فایل تنظیمات مسدودشده
└─ web.config              تنظیمات IIS و امنیت مسیرها
```

## امنیت

- رمزها با `password_hash` و نشست‌ها با `session_regenerate_id` محافظت می‌شوند.
- فرم‌ها و APIهای تغییردهنده CSRF دارند.
- کنترل مالکیت روی داده‌های هر کاربر اعمال می‌شود.
- پوشه‌های `data`، `includes` و `config` از وب مسدود هستند.
- `display_errors` در اجرای عادی خاموش است.
- مانیتورینگ اختیاری است و خرابی MySQL نباید برنامه‌ی اصلی را متوقف کند.
